# Steps: cold-read, row fixer, file approval

Part of Prism (`~/.claude/skills/prism/SKILL.md`). Read when this step comes up.

**coldread** (agent `fg-cold-reader`, after every map): a fresh agent with no context restates every brief scenario and every map regression row and lists what it had to guess. `done coldread pass` is refused while any row has a guess. Then: rewrite the brief rows yourself (wording only, the meaning the user confirmed stays), fix map rows with the **row fixer**, never a full re-map: `graph.py rowfix <p> --rows R-<p>-2,R-<p>-4 --said "<the guesses, quoted>"` prints the prompt; spawn `fg-row-fixer` with it exactly; then `graph.py rowfix-done <p>` checks it returned exactly those ids in valid row shape and swaps them into `map-<p>.json` (a copy of the map before is kept). If refused, send `graph.py fix rowfix:<p>` to the same agent, up to 3 times. Then mark `done coldread blocked --reason "rows rewritten"`, and `graph.py reopen coldread` so a new reader checks them. Report it in one line (`cold-read: 24 rows, 0 guesses`). After the first round, the `coldread` prompt lists **unchanged clean rows** (same row text and same `setup` as the last read, no guesses then); the reader copies those and re-reads only the rest. **At most 3 cold-read rounds**: after the 3rd, never start another on your own; ask the user "skip (accept the remaining guesses) or one more round?" and use their words with `--user-override` or `reopen coldread --said`. `graph.py reopen coldread` refuses a 4th round without `--said`. If the user explicitly accepts the remaining guesses, run `done coldread pass --user-override "<their words>"`; it logs the override and the open guesses in `run.json`. Never use it without the user's words.

**mapcheck** (after `coldread`): show one short table per platform from `map-<p>.json` → `files` (file name, add/change, layer, `what`), and "no change" for skipped platforms. Wait for **yes**.
- yes → write `mapcheck.json` `{"approved": true, "said": "<their words>"}`, then `done mapcheck pass`.
- edits → `graph.py redo map:<p> --said "<their words>" --items <row ids or file names the edit touches | all>` (only the user's words and what they directly imply; never add behaviour they didn't ask for) for each platform named, `done mapcheck blocked --reason "user edited map"`, then `reopen coldread` and `reopen mapcheck`, so the new map is cold-read and shown again.

## Scoped retries (diff check)
A map sent back with `redo map:<p> --items …` may change **only** those items. `redo` saves the approved map as `approved-map-<p>.json`; `done map:<p> pass` compares the new map against it file by file and row by row, and refuses any file or row that was added, removed or changed but isn't in `--items` (`graph.py fix map:<p>` lists them for the same agent). `--items all` is only for a change that really reshapes the plan (the user changed the base branch, the behaviour or the design). Test-row wording is never a map redo: use the row fixer.
